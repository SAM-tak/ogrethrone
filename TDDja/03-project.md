# プロジェクトとランチャー

## 1. 文書の位置づけ

ゲームの中身（レベル・スクリプトなど）を収めるプロジェクトフォルダの扱いと、
エディターを起動したときに出すプロジェクトランチャーを定める。
対象は最初の簡易な段階とし、アセットの取り込み・ビルド・配布は扱わない。

［補足］現状はプロジェクトの概念がなく、すべてのパスがプロセスの作業ディレクトリ基準である。
VS Code の F5 では作業ディレクトリがリポジトリ直下なので、エンジンのリポジトリがそのままプロジェクトフォルダを兼ねている。

## 2. 確定事項

- 引数なしで起動すると、エディターの前にプロジェクトランチャーを表示する（Godot のプロジェクトマネージャーに相当）。
- ランチャーは最初の段階では簡易なものでよい。次の機能を持つ。
  - 新規作成
  - インポート（既存のプロジェクトフォルダの登録）
  - 認識しているプロジェクトフォルダの一覧
  - 一覧の項目をクリックすると、そのプロジェクトを開いてエディターを表示する

## 3. プロジェクトフォルダ

### 3.1. 目印のファイル

［提案］フォルダ直下に `project.throne.lton` があれば、そのフォルダをプロジェクトとみなす。
中身は LTON（L^ 08）で、次の項目を持つ。

```lton
format = "ogrethrone-project",
version = 1,
name = "My Game",
mainLevel = "levels/main.level.lton",   # 省略可
```

［提案］`mainLevel` があれば、プロジェクトを開いたときにそのレベル（04）を開く。
無いとき、またはファイルが無いときは、空のレベルで始める。

### 3.2. 構成

［提案］

```text
<プロジェクト>/
    project.throne.lton
    lhat-host.json      # 言語サーバー用。エディターが生成する（3.4）
    levels/             # *.level.lton（04）
    scripts/            # *.lh。main.lh は省略可（02 の 4.1）
```

### 3.3. パスの基準

［提案］プロジェクト内のパスは、すべて**プロジェクトフォルダ基準の相対パス**とする。
レベルのファイル内のパス（スクリプト、04 のグラフィックのリソース）も、レベルのファイルの場所ではなくプロジェクトフォルダが基準である。
エディターは作業ディレクトリを変更せず、プロジェクトの根を明示的に使ってパスを解決する。

［補足］`ScriptRuntime` はすでにプロジェクトの根を引数に取るため、エディター側で根を渡すだけで済む。

### 3.4. `lhat-host.json`

［提案］プロジェクトを作成したとき、および開いたときに、エディターが `lhat-host.json` を書き出す。
内容が既存のものと同じなら書き換えない。
これにより、エンジン側でバインディングを変えても、プロジェクトを開くだけで言語サーバーの情報が追従する。
`--dump-host-api` は残す。

## 4. ランチャー

### 4.1. 画面

［提案］エディターと同じウィンドウに Dear ImGui で描く。プロジェクトを開くと、同じウィンドウがエディターに切り替わる。

- 一覧: 名前、パス、最後に開いた日時を、最後に開いた順に並べる。クリックで開く。
- 作成: 名前と親フォルダを入力する。`<親フォルダ>/<名前>/` を作り、3.2 の構成と `project.throne.lton` を置いて、一覧に加えて開く。既存の空でないフォルダには作らない。
- インポート: `project.throne.lton` を含むフォルダ（またはそのファイル自体）のパスを入力し、一覧に加える。
- 一覧から外す: 一覧から登録を消すだけで、フォルダは消さない。
- 存在しないフォルダは一覧に残したまま「見つからない」と表示し、開けないようにする。

［提案］フォルダの指定は、最初はパスの手入力とする。OS のフォルダ選択ダイアログは後の段階で加える。

### 4.2. 一覧の保存先

［提案］認識しているプロジェクトの一覧は、ユーザーごとの設定として LTON で保存する。

- Windows: `%APPDATA%/OgreThrone/projects.lton`
- それ以外: `$XDG_CONFIG_HOME/ogrethrone/projects.lton`（未設定なら `~/.config/ogrethrone/projects.lton`）

```lton
format = "ogrethrone-projects",
version = 1,
projects = {
    { path = "C:/Users/.../MyGame", lastOpened = 1792345678 },
},
```

`lastOpened` は UNIX 時刻（秒）とする。

### 4.3. エディターとの行き来

［提案］File メニューに「Close Project」を加え、ランチャーへ戻れるようにする。
未保存の変更があるときは、終了時と同じ確認を出す。

## 5. 起動引数

［提案］

- `ogrethrone`: ランチャーを表示する。
- `ogrethrone <プロジェクトフォルダ>`: ランチャーを飛ばしてそのプロジェクトを開き、一覧にも加える。
- `ogrethrone --smoke`: 一時フォルダに新規プロジェクトを作って開き、3 フレーム描いて終了する。
- `ogrethrone --dump-host-api [file]`: 現状どおり。

## 6. エンジンのリポジトリ

［提案］リポジトリ直下の `scripts/` と `lhat-host.json` は、サンプルのプロジェクト `samples/basic/` へ移す。
起動時のサンプルのレベル（`SceneDocument::example()` 相当）は、このプロジェクトの `levels/main.level.lton` としてファイルにする。
VS Code の起動設定は、引数でこのサンプルを開く構成と、ランチャーを出す構成の 2 つにする。
