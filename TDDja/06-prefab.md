# 入れ子のプレハブとドリルダウン

## 1. 文書の位置づけ

プレハブ（05 の 3 節）を、Unity の入れ子のプレハブに相当するものにする。
あわせて、レベル → シーン → プレハブ（またはレベル → プレハブ）と編集対象を掘り下げる「ドリルダウン」と、シーンノードの階層の編集を定める。

［補足］現状のプレハブは、`*.prefab.lton` という形式で読み書きできるだけで、シーンからプレハブを置く手段も、プレハブを単独で編集する手段もない。
階層の編集は、ドラッグによる親の付け替えと、選択中のノードの子としての追加だけができる。

## 2. 確定事項

- シーン（およびプレハブ）の中に、プレハブのインスタンスを置ける。プレハブの中にも、別のプレハブのインスタンスを置ける（入れ子）。
- インスタンスは、元のプレハブに対する上書きを持てる。範囲は Unity 相当とする。
  - インスタンス内の各ノードのプロパティ（名前・トランスフォーム・色）
  - インスタンス内の Runner の振る舞いの欄の値
  - インスタンス内へのノードの追加・削除
  - インスタンス内への Runner の追加・削除
- プレハブに属する Runner は、インスタンスを置くたびに 1 組ずつ生まれる。その欄のノード参照は、そのインスタンスの中のノードに解決される。
- シーンも「レベルに対するプレハブ」のようなものとして扱い、レベルがシーンのインスタンスの情報を持つ（3.1）。
  - 同じシーンを 1 つのレベルに複数置ける。上書きはインスタンスごとに持つ（Unity と異なる）。
  - シーンのインスタンスは、ルートのトランスフォームを 1 つ持つ。シーンのノードは、すべてその下の子として並ぶ（Unity と異なる。同じシーンをずらして並べるため）。
  - レベルはシーンノードを直接持たない。レベルに置けるのはシーンのインスタンスだけであり、プレハブのインスタンスはレベルに直接置けない（必ずシーンかプレハブの中に置く）。
    どのシーンにも属さないシーンノードを作らないためである。
- ドリルダウンは、その場で切り替える（Unity のプレハブモードと同じ）。エディター全体が掘り下げた先のシーン・プレハブの編集に切り替わり、パンくず（Level > Scene > Prefab）で戻る。
- シーンノードの階層について、次の編集ができる。
  - 兄弟の並べ替え
  - プレハブ化（選んだノードの部分木を `*.prefab.lton` に切り出し、その場所をインスタンスに置き換える）
  - インスタンスの展開（インスタンスを解除して、通常のノードに戻す）

## 3. インスタンスの表し方

インスタンスは、`prefab` を持つシーンノードとする。このノードを**インスタンスノード**と呼ぶ。

インスタンスノードとプレハブの根は、展開すると 1 つのノードになる（Unity と同じ）。

- プレハブの根は 1 つだけとする（`parent = 0` のノードがちょうど 1 つ）。
- インスタンスノードが与えるのは、根の名前と変換（位置・回転・スケール）だけである。色などそれ以外は、プレハブの根の値か、その上書き（4 節）による。インスタンスノード自身の `colour` は使わない。
- インスタンスノードは、自分の子を持たない。
- プレハブの根は、インスタンスノードにできない。別のプレハブを土台にするには、バリアント（3.2）にする。

［補足］当初の案では、インスタンスノードの子としてプレハブの根が並ぶ形だった。この形では、インスタンスノードとプレハブの根の両方がトランスフォームを持つ。また、バリアントを重ねるたびに階層が 1 段深くなる。そのため上の形に改めた。

```lton
{
    id = 5,
    name = "Crate A",
    parent = 0,
    position = {3, 0, 0},
    rotation = {0, 0, 0},
    scale = {1, 1, 1},
    colour = {1, 1, 1},
    prefab = "prefabs/crate.prefab.lton",
    overrides = { ... },    # 4 節
},
```

シーンノードの ID は、`0xFFFFFFFF` 以上 `0x7FFFFFFFFFFFFFFF` 以下のランダムな整数とする（Unity の fileID と同じ考え方）。ファイルをまたいでも事実上重ならない。下限は、小さな値が出て連番のように見えるのを避けるため。`0` は「ノードなし」を表す。読み込みでは、正の整数ならどれでも受け付ける。

インスタンスの中のノードは、インスタンスノードから辿る ID の列（**パス**）で指す。

- プレハブの中のノード `c` は `{c}`、入れ子のインスタンス `n` の中のノード `x` は `{n, x}` である。
- インスタンスノード自身（＝プレハブのルート）は、空のパス `{}` で指す。
- パスの各 ID は、その前の ID のノードの**下のどこか**から探す（直下に限らない）。見つかった最初のものを使う。
  - 部分木をプレハブ化して間にインスタンスが 1 段増えても、古いパス `{x}` は `{n, x}` として見つかる。他のファイルの上書きや参照を書き換える必要がない。
  - 同じプレハブを 1 つのインスタンスの中に複数置くと、同じ ID のノードが複数現れる。どれを指すかは、途中のインスタンスの ID をパスに含めて区別する。エディターが書くパスは、常に途中のインスタンスを全部含む。
- プレハブの中では、ルートも自分の ID を持つ。そのため、インスタンスノードとそのルートは、どちらの ID でも同じノードを指す。プレハブの Runner が自分のルートを参照している場合に、ルートの ID で指す形になる。

［提案］シーンノードへの参照（05 の 4 節の `NodeRef`）に、インスタンスの中を指すパス `inner` を足す（形は 3.1 節）。
`inner` を省略すると、そのシーン自身のノード（従来どおり）を指す。

プレハブが、直接または間接に自分自身のインスタンスを含むことは誤りとする。バリアントの土台を辿って自分に戻る場合も同じ。展開する時とインスタンスを置く時に検査する。

### 3.2. バリアント

バリアントは、ノードを持たず、土台のプレハブ（`base`）とその上書き（4 節と同じ形）だけを持つプレハブである。
拡張子は通常のプレハブと同じ `*.prefab.lton` で、`base` の有無で区別する。

```lton
format = "ogrethrone-prefab", version = 2,
nodes = {}, runners = {},
base = "prefabs/crate.prefab.lton",
overrides = { nodes = { { path = {}, colour = {0, 1, 0} } } },
```

- 展開では、土台を展開してから、バリアントの上書きを適用する。土台がバリアントでもよい（何段でも重ねられる）。
- バリアントのインスタンスも、根は 1 つのノードにまとまる。階層は深くならない。
- バリアントを単独で開くと、土台の根を空のパス `{}` に置いた木になる。そこでの編集は、すべてバリアントの上書きになる。
- エディターでは、バリアントを文字色で区別する（ブラウザーの一覧と、インスタンスノードの横に出すプレハブ名）。アイコンが入ったら、アイコンでも区別する。
- バリアントへのノード・Runner の追加は、上書きの残り（8 節の 4）で扱う。

### 3.1. シーンのインスタンス

レベルは、シーンのインスタンスの情報を持つ。

［提案］レベルの `scenes` は、パスの並びではなく、シーンのインスタンスの並びとする。各インスタンスは、レベルの中で一意な ID、シーンのパス、プレハブのインスタンスと同じ形の上書き（4 節）を持つ。

```lton
scenes = {
    { id = 1, scene = "scenes/room.scene.lton" },
    {
        id = 2,
        scene = "scenes/room.scene.lton",              # 同じシーンをもう 1 つ
        position = {10, 0, 0}, rotation = {0, 90, 0}, scale = {1, 1, 1},
        overrides = {
            nodes = { { path = {1}, position = {0, 2, 0} } },
        },
    },
},
```

［補足］同じシーンを複数置けるので、シーンのノードはシーンのパスでは識別できない。シーンのインスタンスの ID と、その中のパスで識別する。
シーンのインスタンスは、ルートのトランスフォーム（`position`・`rotation`・`scale`）を持つ。シーンの根のノードは、その下に並ぶ。
階層にノードは増やさない。インスタンス自身がトランスフォームを持つ。
`throne.SceneNode` の位置などは、これまでどおり親からの相対である。シーンの根は、シーンのインスタンスからの相対になる。

［補足］Level の段では、Scene パネルのシーンの行を選ぶと、インスペクターにそのインスタンスのシーン・トランスフォーム・上書きの数が出る。トランスフォームはギズモでも動かせる。Delete で、そのインスタンスをレベルから外す。

［提案］シーンノードへの参照（05 の 4 節の `NodeRef`）の `scene` は、シーンのパスではなくシーンのインスタンスの ID とする。

```lton
target = { scene = 2, node = 5, inner = {3, 2} },
```

シーンに属する Runner が同じシーンのインスタンスのノードを指すときは、従来どおり `scene` を省略する。

［補足］Level の段でシーンの中身を編集すると、シーンのファイルではなく、レベルが持つそのシーンのインスタンスの上書きになる（4 節の最後の提案と同じ規則）。
シーンのファイル自体を編集するには、Scene の段へドリルダウンする（6 節）。

## 4. 上書き

［提案］上書きはインスタンスノードの `overrides` に、パスをキーとして持つ。上書きのない項目は、プレハブの値をそのまま使う。

```lton
overrides = {
    nodes = {
        { path = {}, colour = {0, 1, 0} },                # インスタンスノード自身（＝根）の色
        { path = {3}, position = {0, 1, 0} },             # プロパティの上書き（変えた項目だけ）
        { path = {3, 2}, colour = {1, 0, 0} },
    },
    removedNodes = { {4} },                                 # 削除（その部分木ごと）
    addedNodes = {                                          # 追加。parentPath はインスタンス内の親
        { parentPath = {3}, node = { id = 1, name = "Extra", ... } },
    },
    runners = {
        { path = {1}, behaviour = 0, fields = { degreesPerSecond = 45 } },
    },
    removedRunners = { {2} },
    addedRunners = { { id = 1, name = "Extra Runner", behaviours = { ... } } },
},
```

［提案］追加したノードの ID も、ほかのノードと同じ範囲のランダムな値とする。追加した Runner の ID は、そのインスタンスの上書きの中でだけ一意とする。

［提案］エディターでインスタンスの中を編集すると、その変更は上書きとして記録される。インスペクターでは上書きされた項目を強調し、項目ごとに次を選べる。

- **Revert**: 上書きを消し、プレハブの値に戻す
- **Apply**: 上書きをプレハブ本体に書き込み、上書きを消す

## 5. 展開

［提案］エディターとランタイムは、インスタンスを**展開した**ノードの木を扱う。
展開した木の各ノードは、所属するシーンと、インスタンスノードからのパスで識別する。描画・ピック・ギズモ・`throne.SceneNode` は、この展開した木を対象にする。

［提案］展開は、プレハブを読み込み、上書きを適用し、入れ子のインスタンスを再帰的に展開することで行う。
プレハブのファイルは、エディターのセッションの間キャッシュし、ファイルが変わったら読み直す。

## 6. ドリルダウン

［提案］エディターは、編集対象の文脈を積み重ねて持つ。

- **Level**: レベルと、そのすべてのシーンのインスタンス。ここでの編集はレベルの上書きになる（3.1）
- **Scene**: 1 つのシーンのファイルそのもの。Scene パネルでシーンの見出しをダブルクリックして入る
- **Prefab**: 1 つのプレハブだけ。インスタンスノードをダブルクリック、またはブラウザーのプレハブをダブルクリックして入る。
  ［補足］レベルはプレハブを直接置けないので、Level の段から Scene を経ずに Prefab に入るのは、ブラウザーから開いたときである（1 節の「レベル → プレハブ」）。

ビューポートの上部にパンくずを表示し、クリックした段へ戻る。
戻るときに未保存の変更があれば、終了時と同じく保存か破棄かを確かめる。
プレハブを保存すると、それを使うインスタンスは展開し直される。

［提案］Play は、どの段にいても、その時点のレベル（Level の段の内容）を対象にする。

## 7. 階層の編集

［提案］

- **並べ替え**: Scene パネルで、ノードを別のノードの行の上端・下端（行の高さの 1/4）にドロップすると、その上・下の兄弟として並べ替える。行のそれ以外の部分にドロップすると、従来どおりその子にする。
  - 最後の子の下端では、カーソルを左へ（インデント 1 段ぶんずつ）動かすと、親の後ろ、さらにその親の後ろ、と外側の階層に入る（VS Code・Unity と同じ）。
  - 対象は、そのファイル自身が持つノードだけ。インスタンスの中（プレハブから来たノード）の並びは変えられない（Unity と同じ）。プレハブの中の並びを変えるには、そのプレハブに入って並べ替える。変えた並びは、そのプレハブのすべてのインスタンスに反映される。
  - 並べ替えてもノードの ID は変わらない。上書きや参照は ID で指しているので、並べ替えの前後で同じノードを指したままである。
  - 兄弟順は、2D・UI の描画順（同じ優先度なら下ほど手前）と `throne.find` の検索順に効く。実行順には効かない（実行順は Runners パネルで決める）。
- **プレハブ化**: Scene パネルのノードを、ブラウザーの Prefabs タブへドラッグする（Unity と同じ）。`prefabs/<ノード名>.prefab.lton` に、その場で保存する。同名のファイルがあれば番号を付ける。
  - 通常のノードの場合: その部分木がプレハブに移り、元のノードはそのプレハブのインスタンスノードになる。名前と変換はそのまま残るので、見た目は変わらない。移ったノードは ID を変えないので、それを指していた上書きや参照は、書き換えなくてもインスタンスの中で見つかる（3 節）。
  - インスタンスノードの場合: そのプレハブを土台とし、インスタンスの上書きを持つバリアントを作る。元のノードはバリアントのインスタンスになり、上書きは空になる。
  - 既存のプレハブのファイルの上にドロップした場合:
    - そのプレハブのインスタンスなら、上書きをプレハブに書き戻す（Apply）。確認は出さない。上書き保存と同じ意味のため。プレハブの中のノードに書き込み、入れ子のインスタンスの中の分は、そのインスタンスの上書きにする。バリアントなら、バリアントの上書きに加える。
    - それ以外なら、置き換えるかを確認したうえで、プレハブの中身をドロップしたノードで置き換える。そのプレハブ自身を含むことになる場合（循環）と、編集中のプレハブ自身への置き換えは断る。
  - Undo では元の部分木（Apply なら元の上書き）に戻る。保存したファイルは残る（Unity と同じ）。
  - 対象は、Scene・Prefab の段で、そのファイル自身が持つノードだけ。プレハブの根は対象外とする（根を土台にするにはバリアントを作る）。
- **展開**: インスタンスノードを選んで Unpack を実行すると、上書きを適用した展開結果が通常のノードとして置き換わる（新しい ID を振る）。そのインスタンスを指していた参照は、新しい ID に書き換える。

## 8. 段階

［提案］次の順で実装する。

1. データ: インスタンスノード、シーンのインスタンス（レベル側）、パス、プロパティの上書き、展開、循環の検査
2. エディター: ドリルダウンとパンくず、インスタンスの表示と編集（プロパティの上書き、Revert / Apply）
3. 階層の編集: 並べ替え、プレハブ化、展開
4. 上書きの残り: ノード・Runner の追加・削除
5. ランタイム: 展開した木での Play、プレハブの Runner の複製

［補足］実装状況: 1・2・5 を実装済み。ただし次の点が提案と異なる、または未実装。

- Apply（上書きをプレハブへ書き戻す）は未実装。Revert のみ。
- 段を戻っても、開いたシーン・プレハブの編集はエディター内の文書に残り、Ctrl+S でレベルと一緒に保存する。そのため戻るときの確認は出さない。未保存の変更の確認は終了時・プロジェクトを閉じるときのまま。
- 編集中のプレハブは保存前でも展開に反映する（保存を待たない）。
- Play は Level の段に戻ってから始まる。

［補足］段階 3 のうち、並べ替え・プレハブ化・バリアント（3.2）を実装済み。展開（Unpack）は未実装。

［未決］インスタンスの中の兄弟順の上書き（Unity にはない）。必要になったら、上書きに「親ごとの子の並び（ID の列）」を足す。ID で指すので、並びを変えても別のノードにはならない。
プレハブ化しても参照は書き換えない。ID がファイルをまたいで一意で、パスを「下のどこか」で探すため（3 節）。そのプレハブを使う他のファイルの上書きも、そのまま効く。
