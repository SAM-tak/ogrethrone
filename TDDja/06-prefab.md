# 入れ子のプレハブとドリルダウン

## 1. 文書の位置づけ

プレハブ（05 の 3 節）を、Unity の入れ子のプレハブに相当するものにする。
あわせて、レベル → シーン → プレハブ（またはレベル → プレハブ）と編集対象を掘り下げる「ドリルダウン」と、シーンノードの階層の編集を定める。

［補足］現状のプレハブは、`*.prefab.lton` という形式で読み書きできるだけで、シーンからプレハブを置く手段も、プレハブを単独で編集する手段もない。
階層の編集は、ドラッグによる親の付け替えと、選択中のノードの子としての追加だけができる。

## 2. 確定事項

- シーン（およびプレハブ）の中に、プレハブのインスタンスを置ける。プレハブの中にも、別のプレハブのインスタンスを置ける（入れ子）。
- インスタンスは、元のプレハブに対する上書きを持てる。範囲は Unity 相当とする。
  - インスタンス内の各ノードのプロパティ（名前・変換・色）
  - インスタンス内の Runner の振る舞いの欄の値
  - インスタンス内へのノードの追加・削除
  - インスタンス内への Runner の追加・削除
- プレハブに属する Runner は、インスタンスを置くたびに 1 組ずつ生まれる。その欄のノード参照は、そのインスタンスの中のノードに解決される。
- シーンも「レベルに対するプレハブ」のようなものとして扱い、レベルがシーンのインスタンスの情報を持つ（3.1）。
  - 同じシーンを 1 つのレベルに複数置ける。上書きはインスタンスごとに持つ（Unity と異なる）。
  - シーンのインスタンスは変換を持たない（Unity と同じ）。
  - レベルはシーンノードを直接持たない。レベルに置けるのはシーンのインスタンスだけであり、プレハブのインスタンスはレベルに直接置けない（必ずシーンかプレハブの中に置く）。
    どのシーンにも属さないシーンノードを作らないためである。
- ドリルダウンは、その場で切り替える（Unity のプレハブモードと同じ）。エディター全体が掘り下げた先のシーン・プレハブの編集に切り替わり、パンくず（Level > Scene > Prefab）で戻る。
- シーンノードの階層について、次の編集ができる。
  - 兄弟の並べ替え
  - プレハブ化（選んだノードの部分木を `*.prefab.lton` に切り出し、その場所をインスタンスに置き換える）
  - インスタンスの展開（インスタンスを解除して、通常のノードに戻す）

## 3. インスタンスの表し方

［提案］インスタンスは、`prefab` を持つシーンノードとする。このノードを**インスタンスノード**と呼ぶ。
インスタンスノード自身の名前・変換・色は、インスタンス全体の置き場所を表す。プレハブの根のノード（`parent = 0` のもの）は、インスタンスノードの子として並ぶ。

```lton
{
    id = 5,
    name = "Crate A",
    parent = 0,
    position = {3, 0, 0},
    rotation = {0, 0, 0},
    scale = {1, 1, 1},
    colour = {1, 1, 1},
    prefab = "prefabs/crate.prefab.lton",
    overrides = { ... },    # 4 節
},
```

［提案］インスタンスの中のノードは、インスタンスノードから辿る ID の列（**パス**）で指す。
プレハブの中のノード `3` は `{3}`、入れ子のインスタンス `3` の中のノード `2` は `{3, 2}` である。
ID はプレハブのファイルの中でだけ一意なので、パスにすることで入れ子の各段の ID が衝突しない。

［提案］シーンノードへの参照（05 の 4 節の `NodeRef`）に、インスタンスの中を指すパス `inner` を足す（形は 3.1 節）。
`inner` を省略すると、そのシーン自身のノード（従来どおり）を指す。

［提案］プレハブが、直接または間接に自分自身のインスタンスを含むことは誤りとする。読み込み時とインスタンスを置く時に検査する。

### 3.1. シーンのインスタンス

レベルは、シーンのインスタンスの情報を持つ。

［提案］レベルの `scenes` は、パスの並びではなく、シーンのインスタンスの並びとする。各インスタンスは、レベルの中で一意な ID、シーンのパス、プレハブのインスタンスと同じ形の上書き（4 節）を持つ。

```lton
scenes = {
    { id = 1, scene = "scenes/room.scene.lton" },
    {
        id = 2,
        scene = "scenes/room.scene.lton",              # 同じシーンをもう 1 つ
        overrides = {
            nodes = { { path = {1}, position = {0, 2, 0} } },
        },
    },
},
```

［補足］同じシーンを複数置けるので、シーンのノードはシーンのパスでは識別できない。シーンのインスタンスの ID と、その中のパスで識別する。
シーンのインスタンスは変換を持たないので、シーンの根のノードは、そのままレベルの根に並ぶ。

［提案］シーンノードへの参照（05 の 4 節の `NodeRef`）の `scene` は、シーンのパスではなくシーンのインスタンスの ID とする。

```lton
target = { scene = 2, node = 5, inner = {3, 2} },
```

シーンに属する Runner が同じシーンのインスタンスのノードを指すときは、従来どおり `scene` を省略する。

［補足］Level の段でシーンの中身を編集すると、シーンのファイルではなく、レベルが持つそのシーンのインスタンスの上書きになる（4 節の最後の提案と同じ規則）。
シーンのファイル自体を編集するには、Scene の段へドリルダウンする（6 節）。

## 4. 上書き

［提案］上書きはインスタンスノードの `overrides` に、パスをキーとして持つ。上書きのない項目は、プレハブの値をそのまま使う。

```lton
overrides = {
    nodes = {
        { path = {3}, position = {0, 1, 0} },             # プロパティの上書き（変えた項目だけ）
        { path = {3, 2}, colour = {1, 0, 0} },
    },
    removedNodes = { {4} },                                 # 削除（その部分木ごと）
    addedNodes = {                                          # 追加。parentPath はインスタンス内の親
        { parentPath = {3}, node = { id = 1, name = "Extra", ... } },
    },
    runners = {
        { path = {1}, behaviour = 0, fields = { degreesPerSecond = 45 } },
    },
    removedRunners = { {2} },
    addedRunners = { { id = 1, name = "Extra Runner", behaviours = { ... } } },
},
```

［提案］追加したノード・Runner の ID は、そのインスタンスの上書きの中でだけ一意とし、パスでは `0` を目印に区別する（例: `{0, 1}` は追加したノード `1`）。

［提案］エディターでインスタンスの中を編集すると、その変更は上書きとして記録される。インスペクターでは上書きされた項目を強調し、項目ごとに次を選べる。

- **Revert**: 上書きを消し、プレハブの値に戻す
- **Apply**: 上書きをプレハブ本体に書き込み、上書きを消す

## 5. 展開

［提案］エディターとランタイムは、インスタンスを**展開した**ノードの木を扱う。
展開した木の各ノードは、所属するシーンと、インスタンスノードからのパスで識別する。描画・ピック・ギズモ・`throne.SceneNode` は、この展開した木を対象にする。

［提案］展開は、プレハブを読み込み、上書きを適用し、入れ子のインスタンスを再帰的に展開することで行う。
プレハブのファイルは、エディターのセッションの間キャッシュし、ファイルが変わったら読み直す。

## 6. ドリルダウン

［提案］エディターは、編集対象の文脈を積み重ねて持つ。

- **Level**: レベルと、そのすべてのシーンのインスタンス。ここでの編集はレベルの上書きになる（3.1）
- **Scene**: 1 つのシーンのファイルそのもの。Scene パネルでシーンの見出しをダブルクリックして入る
- **Prefab**: 1 つのプレハブだけ。インスタンスノードをダブルクリック、またはブラウザーのプレハブをダブルクリックして入る。
  ［補足］レベルはプレハブを直接置けないので、Level の段から Scene を経ずに Prefab に入るのは、ブラウザーから開いたときである（1 節の「レベル → プレハブ」）。

ビューポートの上部にパンくずを表示し、クリックした段へ戻る。
戻るときに未保存の変更があれば、終了時と同じく保存か破棄かを確かめる。
プレハブを保存すると、それを使うインスタンスは展開し直される。

［提案］Play は、どの段にいても、その時点のレベル（Level の段の内容）を対象にする。

## 7. 階層の編集

［提案］

- **並べ替え**: Scene パネルで、ノードを別のノードの「間」（上端・下端の細い領域）にドロップすると、その位置の兄弟として並べ替える。ノードの「上」にドロップすると、従来どおりその子にする。
- **プレハブ化**: ノードを選んで Create Prefab を実行し、保存先（`prefabs/...prefab.lton`）を指定する。部分木はプレハブに移り、元の場所にはインスタンスノードが置かれる。
  インスタンスノードは元のノードの変換を受け継ぎ、プレハブの根は単位変換になる。そのため、見た目の位置は変わらない。
  その部分木を指していた参照は、インスタンスの中へのパスに書き換える。
- **展開**: インスタンスノードを選んで Unpack を実行すると、上書きを適用した展開結果が通常のノードとして置き換わる（新しい ID を振る）。そのインスタンスを指していた参照は、新しい ID に書き換える。

## 8. 段階

［提案］次の順で実装する。

1. データ: インスタンスノード、シーンのインスタンス（レベル側）、パス、プロパティの上書き、展開、循環の検査
2. エディター: ドリルダウンとパンくず、インスタンスの表示と編集（プロパティの上書き、Revert / Apply）
3. 階層の編集: 並べ替え、プレハブ化、展開
4. 上書きの残り: ノード・Runner の追加・削除
5. ランタイム: 展開した木での Play、プレハブの Runner の複製

［補足］実装状況: 1・2・5 を実装済み。ただし次の点が提案と異なる、または未実装。

- Apply（上書きをプレハブへ書き戻す）は未実装。Revert のみ。
- 段を戻っても、開いたシーン・プレハブの編集はエディター内の文書に残り、Ctrl+S でレベルと一緒に保存する。そのため戻るときの確認は出さない。未保存の変更の確認は終了時・プロジェクトを閉じるときのまま。
- 編集中のプレハブは保存前でも展開に反映する（保存を待たない）。
- Play は Level の段に戻ってから始まる。
