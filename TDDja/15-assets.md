# アセットとブラウザ

## 1. 文書の位置づけ

プロジェクト内のファイル（アセット）の置き場所、移動・リネームに強い参照、エディターの Browser を定める。
03 3.2・3.3 のフォルダ構成とパスの基準を置き換える。

## 2. 確定事項

- アセットは `assets/` の下に自由に置く。種類ごとのフォルダ（`levels/`、`scenes/`、`prefabs/` など）は強制しない。
- ファイル内に書くアセットのパスは `assets/` 基準とする。`@ogre/` で始まるパス（OGRE のサンプル素材）は従来どおり別扱い。
- `main.lh`、`project.throne.lton`、`lhat-host.json` はプロジェクトの根に置く。
- 参照はパスから独立した永続 ID で行う。ID は移動・リネーム・内容の編集では変わらない。複製すると新しい ID になる。
- ID の保存先:
  - エンジンが構造を管理する `.lton`（レベル、シーン、プレハブ、ミキサー）は、トップレベルの `id`。
  - それ以外のファイル（FBX、画像、音声、動画、`.lh`、CSV、その他の `.lton` など）は、付随ファイル `<ファイル名>.meta`（例: `ogre.fbx.meta`）。
- `.meta` の中身は LTON 記法で書くが、拡張子は `.lton` にしない。L^ の言語サーバーの走査・解析対象から外すため。エディターの AssetDatabase がデータとして読み、検証する。
- 参照先が消えたときは、ID を残したまま Missing として表示する。同じパスに別のファイルができても、自動でつなぎ替えない。
- パスや内容のハッシュは永続 ID にしない。
- ID で参照するのはファイルへの参照に限る。`AnimatorComponent.clip`（モデル内のクリップ名）のような、ファイル内の名前は対象外。
- 参照にはハード参照とソフト参照がある（6 節）。
- Browser は、左にフォルダのツリー、右に選んだフォルダのファイル一覧（グリッドとリストを切り替え）を置く（7 節）。
- サムネイルは段階的に作る。最初は種類ごとのアイコンと画像ファイルの実画像、次にモデル・プレハブ・シーンを描画したプレビュー（8 節）。

## 3. プロジェクトフォルダ

```text
<プロジェクト>/
    project.throne.lton
    main.lh
    lhat-host.json
    assets/            # アセット。下の構成は自由
    baked/             # 焼き込みの結果（4.5）
    .throne/           # エディターのキャッシュ（索引、サムネイル）。バージョン管理しない
```

［補足］`main.lh` は Browser に出さない。`project.throne.lton` の `mainLevel` はレベルへの参照（ID）になる。

## 4. 永続 ID と AssetDatabase

### 4.1. ID の形式

ID はノードの ID と同じ Snowflake ID（64 ビット: 時刻、プロセスごとに乱数で選ぶワーカー番号、同じミリ秒内の連番）とし、LTON には整数で書く。アセット用に独自のエポックの生成器を持つ。
［補足］同時に動く 2 つのエディターでもワーカー番号が違えば衝突しない。重複は検出もする（4.3）。

### 4.2. `.meta` の中身

```lton
format = "ogrethrone-meta",
version = 1,
id = 7484712563498500123,
```

将来、インポート設定（法線マップの規約など）もここに置く。その種類と値には、表示名と独立した安定した値を使う。

### 4.3. AssetDatabase

プロジェクトを開くとき `assets/` を走査し、ID と現在のパスの対応表を作る。

- エンジンが管理する `.lton` はトップレベルの `id` を、それ以外は `.meta` を読む。
- `id` の無い管理対象の `.lton`、`.meta` の無いファイルには、新しい ID を振って書き込む。
- 同じ ID が 2 つ以上あれば（`.meta` ごと外部でコピーされた場合）、前回の索引でその ID を持っていたパスを残し、残りに新しい ID を振って Console に出す。前回の索引にどれも無ければ、パスの辞書順で最初のものを残す。
- 本体の無い `.meta` は消さずに Console と Browser で警告し、Browser から削除できる。
- 走査結果（パス、更新時刻、ID）を `.throne/` に索引としてキャッシュし、次回は更新時刻が変わったファイルだけを読む。
- エディターが前面に戻ったとき、および Browser の Refresh で再走査する。

### 4.4. 移動・リネーム・複製・削除

Browser の操作は AssetDatabase を通す。

- 移動・リネームは、本体と `.meta`（あれば）を一緒に動かし、対応表のパスを更新する。参照元のファイルは書き換えない。
- 複製は本体だけをコピーし、新しい ID を振る（管理対象の `.lton` は中の `id` を書き換える）。
- 削除は確認してから行う。参照元は書き換えず、Missing になる。
- エディターの外で動かすときは、本体と `.meta` を一緒に動かす必要がある（README に書く）。

### 4.5. 焼き込みの結果

シーンの GI の焼き込み（現在はシーンの横の `<名前>.gi/`）は、`baked/gi/<シーンの ID>/` に置く。シーンを移動・リネームしても付いていく。バージョン管理の対象とする（焼き込みは時間がかかるため）。

## 5. 参照の保存形式

### 5.1. ファイル内の表現

参照はアセットの ID の整数で書く。

```lton
model = { asset = 7484712563498500123, directXNormals = true^ },
```

参照に人が読むためのパスは併記しない。

### 5.2. 手書きのパス

手書きの便宜のため、参照の位置に文字列のパス（`assets/` 基準）も書ける。読み込み時に対応表で ID に解決し、次に保存するときに ID で書き直す。解決できなければ、そのパスのまま Missing とする。
［補足］これがサンプルの移行手段にもなる（10 節）。

### 5.3. メモリ上の表現

コンポーネントなどは参照を `AssetId` で持ち、使う直前に AssetDatabase でパスへ解決する。OGRE・ufbx・SoLoud などの下層には、解決後のパスを渡す。移動・リネームしても、メモリ上のデータは書き換えずに済む。

### 5.4. 対象

ID で参照するもの:

- レベルのシーン（`scenes[].scene`）、ミキサー（`mixer`）
- プロジェクトの `mainLevel`
- ノードの `prefab`、バリアントの `base`
- Model の `path`、材質変更の `diffuseMap`
- PBS Material のテクスチャ、Light の `mask`
- Particle System の `script`、Audio Source の `clip`
- Behaviour・Render Event の `script`（上書きの `script` も）、System の付加の `script`
- シーンの照明の `environment`

［補足］ID にしないもの: `@ogre/` のパス、FBX が内部に持つテクスチャの相対パス（FBX を動かすときはテクスチャも一緒に動かす）、スクリプトの文字列（`throne.playLevel("…")` など）。

スクリプトがアセットを指すときは、アセット参照の型のメンバーを `@export` し、Inspector で指定する（Behaviour の `data` に ID で保存する）。名前やパス・ID から引く `throne.AssetDB.find(…)` のような API は後で用意する。

L^ のスクリプトが読み込むファイルのパス（`require` など、ローダーに渡るもの）は `assets/` を根とする。`assets/` の外（`..` で上る、絶対パス）は受け付けない。`main.lh` だけはプロジェクトの根から読む。
［補足］言語サーバーは上位のディレクトリへの `require` を通してしまうので、`lhat-host.json` 側でそれを禁止する設定を足すことになる見込み。

## 6. ハード参照とソフト参照

参照の種類は、値ごとではなく欄（スキーマ）ごとに決める。

| 参照 | 出荷時に収集する | 参照元を読み込むとき |
| --- | --- | --- |
| ハード | する | 参照先も読み込む |
| ソフト | する | ID だけ持ち、読み込まない |
| 任意 | この参照だけでは収集しない | ID だけ持ち、読み込まない |

- 5.4 の欄は、`mainLevel` を除きハード参照とする。`mainLevel` はソフト参照とする。
- ソフト参照の取得は、読み込みを起こさない `tryGet()`（読み込み済みならそのハンドル、未読み込み・読み込み中なら nil）と、明示的な `loadAsync()` に分ける。`tryGet()` が返したハンドルは、保持している間アンロードを防ぐ。
- 出荷ビルドは、指定したルート（レベルなど）から、収集する参照を保存データだけで辿って集める。スクリプトが動的に選ぶアセットは、収集対象の一覧で宣言する。

［補足］実行時の読み込み管理（リソースマネージャー）と出荷ビルドはまだ無いので、本書の範囲では欄の種類を決めておくだけとする。

## 7. Browser

- 左ペインは `assets/` を根とするフォルダのツリー。右ペインは選んだフォルダの中身（フォルダとファイル）。
- 右ペインはグリッド（サムネイルと名前）とリスト（アイコン、名前、種類、更新日時）を切り替える。グリッドはサムネイルの大きさを変えられる。
- 上部にパンくずと、名前と種類の絞り込み。
- 種類は拡張子で判別する: レベル、シーン、プレハブ、ミキサー、スクリプト（`.lh`）、モデル（`.fbx`、`.mesh`）、テクスチャ（`.png`、`.jpg`、`.dds`、`.tga`）、HDR（`.hdr`）、音声（`.wav`、`.ogg`、`.mp3`、`.flac`）、パーティクル（`.particle2`）、その他。`.meta` は出さない。
- ダブルクリック: レベルは開く、シーン・プレハブはドリルダウン、モデルは Model のステップ、ミキサーは Mixer パネル、スクリプトは OS の既定のエディター。
- 右クリックのメニュー: 新しいフォルダ、新しいレベル・シーン・プレハブ・ミキサー・スクリプト、リネーム、複製、削除、エクスプローラーで表示、パスのコピー。
- ドラッグ:
  - ファイルやフォルダをツリーのフォルダ、または右ペインのフォルダへ落とすと移動。
  - Hierarchy のノードを落とすとプレハブ化（落とした先のフォルダに作る。06 7）。既存のプレハブのファイルへ落としたときは現在と同じ（置き換えの確認、自分のプレハブなら上書きの適用）。
  - プレハブやモデルを Hierarchy・ビューポートへ落とすと、インスタンスや Model を持つノードを追加する。
- Hierarchy の Add Scene・Add Instance の入力欄はやめ、Browser で選んでいるファイルを使う（またはドラッグ）。
- 従来の Levels・Scenes・Prefabs・Models・Mixers のタブはやめる。Console は別のタブとして残す。

## 8. サムネイル

- 第 1 段: 種類ごとのアイコン（色付きの角丸と種類の略記を ImGui で描く）。画像ファイルは OGRE で読み、縮小したものを出す。
- 第 2 段: モデル・プレハブ・シーンをオフスクリーンで描いたプレビュー。`.throne/thumbnails/<ID>.png` にキャッシュし、本体の更新時刻が変わったら作り直す。
- 表示中のものだけを、1 フレームに数件ずつ作る。

## 10. 移行

後方互換は保たない。

- サンプルの `levels/`、`scenes/`、`prefabs/`、`scripts/`、`mixers/` と素材のフォルダを `assets/` の下へ移す（パスは `assets/` 基準なので、中のパスはそのまま有効）。
- `ogrethrone --resave-assets <プロジェクト>` で全アセットを読み込み・保存し、`id`・`.meta` の付与と、参照の ID への書き換えを行う（5.2）。
- 別途ダウンロードする素材（Bistro、RPG Characters）の置き場所を各 README で `assets/` 下に改める。
- 新規プロジェクトの雛形は `assets/main.level.lton` と `assets/main.scene.lton` を作る。
