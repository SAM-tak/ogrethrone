# Clustered Forward と影

## 1. 採用方針

既定の描画に OGRE-Next の Forward Clustered を使う。Primitive は HlmsPbs の物理ベースの照明を受ける。影は深度シャドウマップを使い、太陽光には PSSM（Cascaded Shadow Maps）を適用し、PCF で境界をフィルターする。

［補足］Clustered Forward はローカルライトの割当てを行い、影は独立した深度アトラスから評価する。この組合せは OGRE-Next が備える HlmsPbs と CompositorShadowNode を使って実装する。独自の照明シェーダーやスクリーン空間だけの影は追加しない。

## 2. 現在の既定設定

［補足］現実装の数値は次のとおりとする。明示指定がないレベルのプレビュー照明に用いる。レベルの rendering に Forward 方式・範囲、クラスタ表示、グリッドを、シーンの lighting に環境光、既定太陽光の有無、空、トーンマッピング、露出、HDR 環境、GI を保存する（13）。

- Forward Clustered: 16×8×24 セル、セルあたり最大 96 ローカルライト、奥行き範囲 0.1〜100。
- 太陽光: Directional Light、方向 (-0.6, -1, -0.4) を正規化、power scale は π。
- 環境光: 上半球 RGB (0.22, 0.25, 0.30)、下半球 (0.06, 0.07, 0.09)、上向き軸は +Y。
- 太陽光の影: 3 段 PSSM。近い段は 2048²、残りは各 1024²。1 枚の 2048×3072 深度アトラスに配置する。
- PSSM: 最初の 2 段を安定化し、lambda 0.7、split padding 1、blend 0.125、fade 0.2、影の遠方距離は 100。
- フィルター: HlmsPbs::PCF_3x3。深度比較とバイアス処理には OGRE-Next の標準実装を使う。
- Primitive の材質: 粗さ 0.65、誘電体の Fresnel 0.04、拡散色は Component の colour。

［補足］Light Component は Directional、Point、Spot、AreaApprox、AreaLtc に対応する。影用の枠は Directional 1 個のままであり、既定太陽を無効にすれば、配置した Directional が利用する。Point／Spot の影と Area Light のソフトシャドウは未実装。Area Light は Clustered のリストではなく通常 Forward の枠から評価する。

## 3. ジオメトリとエディター表示

Primitive の各頂点は外向きの単位法線、UV、接線を持つ。箱は面ごとの法線、Sphere／Capsule は曲面法線、Plane は +Y を使い、三角形の向きを揃える。従来の頂点色に焼き込んだ明暗は使わず、PBS で照明と影を計算する。

Plane を含めて両面照明とし、Primitive は影を落とし、他の Primitive の影も受ける。グリッド・選択枠・ImGui は非照明表示を保つ。グリッドと選択枠は影を落とさない。

View → Shadows は太陽光の影だけを切り替える。拡散光と環境光は保ち、シーンファイルや物理シミュレーションは変更しない。この切替はエディターの表示状態で、保存対象ではない。

## 4. 実行との関係

［補足］ビューポートの既定のスカイボックスには OGRE-Next の AtmosphereNpr によるプロシージャルな青空と太陽を使う。View → Skybox で表示を切り替える。既定の Directional Light と太陽の方向を合わせるが、Light 自体は Atmosphere にリンクせず、既存の照明・環境光の値を保つ。fogDensity は 0 とする。LDR のビューポートに合わせ、skyPower は 0.5、horizonLimit は 0.15 とし、下向きの視線では地平線以下の落ち着いた色を使う。

［補足］空は背景深度の画面矩形として描画し、カメラに応じた視線から色を求める。シーンノード・物理ボディ・ピッキングの対象には追加しない。Quad.program と Atmosphere.material、および対応する GLSL／Any の固定済みリソースだけを読み込む。Editor 終了時は Atmosphere と専用リソースグループを破棄する。View の切替は表示状態のみであり、初期の空の有無はシーンの lighting.sky に保存する（13）。

OGRE は従来どおりメインスレッドで、完成済みの描画用の写しを使う。影の深度描画と本描画は同じ OGRE ノードの配置を参照するので、物体と影は同じ時点を表示する。Box3D のワーカーは OGRE オブジェクトや影のテクスチャーを操作しない。

ビューポートのリサイズで Workspace を作り直しても、同じシャドウノード定義を再利用する。HlmsUnlit と HlmsPbs のテンプレートは固定済みの OGRE サブモジュールから読み込む。

## 5. 検証

［補足］View → Statistics で、ビューポート右上の簡易統計表示を切り替える。既定は表示。−／＋ボタンで通常表示と FPS・VSync の最小表示を切り替える。ImGui のフレーム時間の移動平均からエディター全体の FPS と ms/frame を示し、描画用の写しにあるノード数と、Play の物理ボディ数を併記する。ボタンはクリック可能とし、パネル外では通常のナビゲーションを使う。

エディターの VSync は既定オン。統計表示のチェックで切り替え、エディター内の Play にも同じ設定を使う。ランチャーやシーンビューのタブが隠れた場面では VSync を強制オンにし、シーン用 Workspace を無効にする。再表示時は保持していたチェック状態に戻す。UI とシーンビューは同じウィンドウに出るため、VSync はウィンドウ全体に作用する。

［補足］同期は Vulkan の FIFO 方式を使い、変更時だけ GPU の処理完了を待ってスワップチェーンを切り替える。オフ時は対応していれば IMMEDIATE となる。物理・スクリプトの実行はシーンビューの可視性と独立させるため、Play 中に別タブへ移ってもゲーム進行は継続する。

Systems の OGRE を選択すると Inspector に本番用 VSync（プロジェクト単位）と、Forward 方式・トーンマッピング・露出（レベル単位）を表示する。画角はシーンビューのカメラの設定（保存しない。レベルのインスペクター）と、Camera コンポーネントの設定（07）に移した。本番用 VSync の保存は 03 による。エディター用設定の変更はプロジェクトを変更扱いにせず、本番用設定の変更は Save／Undo の対象とする。

Box3DStep・Animation などほかのエンジン段も OGRE と同じように選択できる。現在は Inspector に名前だけを表示し、設定欄は持たない。今後の物理・アニメーションの設定を置く場所とする。

［補足］展開時は steady_clock による CPU 側の壁時計時間も示す。UI、スクリプト／段の進行、描画用の写しのコピー、物理結果の反映と入力準備、Box3D の計算、OGRE ノード同期、renderOneFrame、物理完了待ちを分け、約 0.5 秒で平滑化する。Box3D の時間はワーカー側で計測し、結合後に公開する。描画と物理は並行なので合計しない。renderOneFrame は CPU の描画処理に加え、GPU・ドライバー・表示待ちも含み、GPU 単体のタイマーではない。

［補足］`--profile-physics [project] [output.csv]` は物理サンプルの一時コピーを 1/60 秒の固定刻みで実行し、300〜329 ボディのフレーム平均と各フレームの CSV を出力する。既定の CSV は out/physics-profile.csv。計測ではメインループの sleep を省き、VSync を無効化する。表示 FPS は固定刻みの影響を受けるので、比較には壁時計の ms を使う。元のプロジェクトとプロジェクト一覧は変更しない。

［補足］2026-10-19 の実測例（Ryzen 5 2600／GTX 1660 Ti、clang-cl、ウィンドウ 1280×720、既定の空と影、並行実行、300〜329 ボディの 180 フレーム平均）:

| フレーム全体の処理 | 29.581 | 3.589 |
| UI | 5.697 | 0.567 |

［補足］この条件では描画経路がフレームの主因であり、物理ステップは並行実行の内側に収まっている。Release との差から Debug の CPU 側の処理・検査コストが大きいと判断できる。ただし描画／表示待ちを GPU 時間と同一視しない。箱ごとに個別の ManualObject・PBS Datablock を作る現実装であり、個数だけから GPU の限界とは判断しない。全体処理時間の逆数も、実際の表示 FPS を保証するものではない。CSV は out/physics-profile-debug.csv と out/physics-profile-release.csv。

`samples/physics` を開いて F5。球・カプセル・箱の移動に追随する影が地面と台へ落ちる。View → Shadows で比較できる。

CPU テストは、各 Primitive の法線が単位長であること、三角形の表向きと法線が一致することを検証する。

`--smoke-navigation` は空 ON／OFF の描画画像の背景画素が変わることと、再表示で元に戻ることも検査する。空を表示した状態でフライ・Orbit・フォーカス・パン・ドリーの入力再生テストを実行する。

Vulkan の `--smoke-physics` は Forward Clustered が選択されていることを確認し、同じ初期配置の影 ON／OFF の画像が異なることを検査する。Play 中の移動と、Stop 後に影が再び現れることも検査する。

［補足］PSSM のカメラ合わせにより、同じ配置へ戻しても PCF 境界に微小な画素差が出ることがある。そのため Stop の復元は影 OFF 同士の画像で完全一致を要求し、影の復元は別に ON／OFF の差分で確認する。画像は 2／3／60／240／244／245 フレーム目の PPM を出力する。

## 6. マテリアルとショーケース

［補足］PBS Material Component は粗さ、Fresnel F0 または金属度、発光、UV スケール、Diffuse／Normal／Roughness／Specular／Reflection の画像パスを保持する。Primitive の colour が拡散色となる。Light とともに Inspector で追加・編集・削除でき、プレハブの既存 Component に対する値の上書きにも対応する。画像はプロジェクト相対パスを基本とし、@ogre/ のみ固定済み OGRE Media を参照する。

［補足］samples/showcase に Forward3D、PbsMaterials、AreaApproxLights の配置を Throne のレベル／シーンとして移植する。メッシュは組み込み Primitive を使い、元の岩・大理石・反射画像を再利用する。Forward3D は 128 点光源、64 本の柱と 16 個の回転物体、他の 2 レベルは 8×8 の粗さ／Fresnel 球列と 16 個の回転物体を持つ。Area の 2 光源はマスク付き Approx と LTC のプレビュー切替に対応する。

［補足］Lighting メニューの Forward 方式とクラスタ表示はレベルへ保存し、Area の全光源切替は比較用の一時状態とする。永続的な方式変更は個々の Light.type に保存する。元アプリの F キーは引き継がず、F5 と Pause を Throne の Play／Pause に使う。検証は showcase_data_smoke と --smoke-showcases で行う。

## 7. ParticleFX2

［補足］Particle System Component は ParticleFX2 のテンプレート名、任意のプロジェクト相対 .particle2 パス、有効フラグを持つ。Inspector で編集でき、シーン保存、プレハブ上書き、query("ParticleSystem") に対応する。空のパスは組み込みの 5 テンプレートを参照する。

［補足］particlefx2.level.lton は元の噴水、光輪、PBS 煙、Unlit 煙、PBS 球粒子と移動台・マーカーを移植する。元の煙定義は Affector の継承が衝突するため、media/particles/Showcase.particle2 で継承を展開し、Scaler／Rotator／ColourImage を分離する。色の増加率の先頭 + も除去し、charconv で元の数値を読み取れるようにする。画像と HLMS 材質は固定済み OGRE Media を利用し、単独の大理石 Billboard は縦の Plane で表す。

［補足］粒子プレビューは編集時も動作し、Particles メニューで停止・再開・再スタートできる。Play 開始と Stop で共有粒子プールを消去し、Pause 中は OGRE ControllerManager の時間係数を 0 にして放出・位置・寿命を停止する。OGRE のフレーム時間には Throne の dt を渡す。カメラと UI は継続する。テンプレートや有効フラグの変更もプールを再スタートする。

［補足］Particles メニューで Alpha Blending／Alpha Hashing を比較できる。単一サンプルのビューポートなので MSAA A2C の比較は含めない。統計にシステム数と粒子の概数（SIMD の処理枠数）を表示する。--smoke-showcases は 4 レベルを開き、5 系統を単独表示した際の描画、停止中の全生存粒子の位置・寿命、方式変更、Stop の消去、再入場を検査する。

［補足］光輪の aureola.png は輝度＋アルファの PNG で、STBI は RG8 として読み込む。通常の RGBA 読み取りでは存在しない A が 1 となり、透明な四隅に黒い板が現れる。Unlit の読み取りを R→RGB、G→Alpha に割り当てる。描画テストは光輪の単独表示で背景の一様色が黒く覆われないこと、アルファブレンドと深度書き込み OFF を検査する。

［補足］シーンの RGB は背景と粒子を合成済みだが、描画先の Alpha は粒子によって変わる。ImGui の標準 Image 材質でこれを再度透過合成すると、RGB のキャプチャでは正常でも UI には黒い四角が現れる。ビューポート専用の Image 材質だけを不透明コピーにする。固定済み ImGui バックエンドが prepareForRender で生成するテクスチャ別材質を設定し、フォントなど他の UI の透過は維持する。--smoke-showcases は影を有効にした粒子シーンについて、光輪単独と Alpha Blending／Hashing のウィンドウ出力を取得し、UI 表示部分を除いた画素がシーンの RGB と一致することも検査する。

## 8. モデルと環境マップ

［補足］Model Component はプロジェクト相対の FBX パスと、法線マップが DirectX 規約かどうかのフラグを持つ。読み込みは ufbx（v0.23.1、MIT、third_party/ufbx）で、メートル・+Y 上・右手系へ変換する。ファイルは ModelLibrary が一度だけ読み、サブメッシュごとの OGRE Mesh とマテリアルごとの PBS データブロックを共有する。配置はメッシュインスタンスのサブメッシュごとに Item を作り、Item はそのマテリアルの描画キューで描く（不透明部分が屈折パスで深度を書かない）。不透明マテリアルの Item だけが影を落とす。ファイル内のライトとカメラは配置しない。Model だけのノードは、モデルの境界を選択枠とピックに使う。FBX は発光の強さを持たない（係数 1・色 0.5）ので、Model Component の emission が発光マップの最大値の放射輝度を決める（既定 1。太陽 150 の下では灯具が光って見えない）。Bistro 外観は 30。

［補足］マテリアルはメタリックワークフロー。テクスチャは WRAP と異方性 8 でサンプルする（OGRE 既定の CLAMP では、UV が 0〜1 を超えるタイル模様が端の色一色になる）。FBX の透過色（transparency_color × factor）を持つマテリアルは透明な誘電体とみなす。拡散なし、粗さ 0.05、非金属（ファイルの ORM は使わない。曇って見えるため）、深度書き込みなし。既定は OGRE の Refractive モードで画面空間屈折（強さ 0.05、両面）とし、その Item を描画キュー 200（屈折パス）に置く。

液体の吸収: Model Component は materials に名前ごとの変更を持つ（name、absorption［1/m、RGB］、thickness［m］）。吸収を持つ透過マテリアルは体積とみなし、ベール＝ランベルト則の透過率 T = exp(−absorption × thickness × |N·V|) をシェーダーの出力とし（カスタムピース custom_ps_posExecution）、乗算ブレンド（dst × src）で背後を着色する。丸い容器の弦は中央で長いので |N·V| を掛ける（法線が内向きの液体にも対応するため絶対値）。表面のみ描く。描画キューは 99（不透明パスの最後）で、手前のグラス（キュー 200）は着色済みの画像を屈折して見せる。屈折は第 1 パスの画像だけを背景にできるため、液体をグラスと同じ屈折パスに入れると上書きされる。データブロックのカスタムピースはステージごとに 1 つなので、ORM と吸収のピースは 1 つの文字列に結合する。ピースの名前は内容のハッシュとし、同じピースのマテリアルはシェーダー（影キャスターを含む）を共有する。マテリアル名で付けると、OGRE はピース名をハッシュに含めるので全マテリアルが別シェーダーになり、Bistro 内装を開くと 1 フレームで約 180 本をコンパイルしていた。samples/bistro の interior-wine は pyscene の吸収係数（赤ワイン・白ワイン・ビール・ワイン瓶）を使う。BaseColor（アルファは不透明度、DXT5 ならアルファテスト 0.5 と両面）、Normal、glTF 式 ORM（R=遮蔽、G=粗さ、B=金属度）、Emissive を使う。ORM はデータブロック単位のカスタムピースで SampleSpecular／SampleRoughness の参照チャンネルを差し替え、既存のショーケース材質には影響させない。DirectX 法線は接線の w 符号で扱う。

［補足］シーンの lighting（以前はレベルの rendering。13）は environment（プロジェクト相対の正距円筒 HDR）と environmentScale を持つ。CPU で 512² のキューブマップ（2×2 スーパーサンプル）と 9 係数の球面調和へ変換する。ミップは OGRE の IblSpecular 計算パス（Compute/Algorithms/IBL）で GGX 粗さ別に事前フィルタする。キューブマップは空と、自前の反射マップを持たない全 PBS マテリアルの反射に、球面調和は AmbientSh の拡散環境光に使う。放射輝度は 16（environmentScale を掛ける前）で打ち切り、HDR 内の太陽は Light Component の平行光源に任せる。空の太陽は既定の太陽か、最初の平行光源 Component の向きに追従する。

［補足］ビューポートは、まずライティングする不透明体（描画キュー 10）を深度プリパスで描き、深度と G-buffer（ビュー空間法線 RGB10A2、太陽の影と粗さ RG16、モーションベクトル RG16F）を書く。影ノードはここで計算する。次にシーンを RGBA16F に描く。キュー 10 はプリパスを使って Opaque へ描き（深度は読み取り専用、法線マップと太陽の影は G-buffer から読む）、続けてキュー 11〜199（空 11、Unlit の線とエミッター 12、パーティクル 15、吸収体 99）を通常どおり描く。HlmsUnlit はプリパスに対応しないので、Unlit の物体はキュー 12 に置く。Opaque を Hdr へ複製し、キュー 200 以上を Opaque と深度を屈折元として Hdr へ描く（影ノードは再利用）。

［補足］OGRE の注意点 2 つ。(1) 非 MSAA の use_prepass でも HlmsPbs はプリパス深度用のテクスチャスロットを空けるので、深度テクスチャ名を渡さないと後続のテクスチャ（BRDF の LUT など）が 1 つずれ、環境光が消える。(2) use_prepass では LoadGeomNormalData が省かれ、点光源・スポットライトの影の法線オフセットが未初期化の geomNormal を使っていた。フォークのテンプレートで常に読むよう直した。CompositorPassSceneDef の mLastRQ は排他的（その番号を含まない）。

［補足］モーションベクトルは、前フレームからの UV の変化（今の UV − 前の UV）。HlmsListener の MotionVectors がプリパスでだけ custom_motion_vectors を立て、前フレームのビュー射影（HlmsPbs の viewProj と同じく描画先に合わせて反転）をパスバッファに渡す。頂点シェーダーが今と前のクリップ座標（x, y, w）を補間し、ピクセルシェーダーが w で割って差を出す（media/pbs）。物体の前フレームのワールド行列は HlmsPbs のサブクラス ThronePbs が描画ごとに書く。ReadOnlyBuffer のスロット 1（prevWorldBuf）を全パスで予約し（mReservedTexBufferSlots を 2 に）、プリパスでは HlmsPbs の定数バッファ 1 つごとに 1 本のバッファ（drawId はそこで 0 に戻る）へ、物体（MovableObject）ごとに覚えた前フレームの行列を書く。前フレームに描かれなかった物体は動いていないとみなし、記録は捨てる。スキン・ポーズのメッシュは対象外（今は無い）。何も描かれない空は 0 のまま残すので、使う側が深度から再投影する。HlmsPbs のリスナーは 1 つしか付けられないため、HlmsListenerChain がモーションベクトルと GI のリスナーを順に呼ぶ。パスバッファの並びも同じ順で、custom_passBuffer ピースが両者のピース（motionPassBuffer、aifPassBuffer）をその順に挿入する。その後クアッドパス（media/postprocess/Tonemap）で露出（EV）を掛けて表示先へ書く。レベルの toneMapping が真なら ACES フィルミック曲線（Narkowicz の近似）、偽なら従来どおりクランプする。既定は偽・EV 0 で、既存レベルの見た目は変わらない。

［補足］TAA（時間方向アンチエイリアス）。ビューの AA 手法（レベルのインスペクター、Camera コンポーネントの antiAliasing と同じ選択肢: TAA（既定）／SMAA／None）で選ぶ。SMAA の 3 パスと、トーンマップ後の画像をそのままコピーするパスは、ワークスペースの実行マスクで切り替える（TAA と None はコピー、SMAA と正射影の TAA は SMAA）。透視カメラを Halton (2, 3) 列の 8 通りのサブピクセルだけずらして描き（Frustum::setFrustumOffset、描画後に戻すので選択やギズモは揺れない）、Hdr の後のクアッドパス（media/postprocess/Taa）で前フレームまでの履歴（TaaHistory、DiscardableContent を外して保持）と混ぜる。今フレームの色は 3×3 の標本をジッタ込みの位置から画素中心までの距離でガウス（Blackman-Harris の近似）重みにして作る。履歴の位置はモーションベクトルから、そのジッタの変化を引いて求める（3×3 で最も手前の面の値を使い、輪郭を手前の物と一緒に動かす）。何も描かれない空は、深度とカメラの再投影（今のクリップ空間から前フレームへの行列）で求める。履歴は 3×3 の色の範囲（YCoCg の AABB）へクリップし、今フレーム 0.1 の重みで、輝度の逆数で重み付けして混ぜる。画面外へ出る、ビューが隠れていた、ターゲットを作り直した、視点を切り替えた（Align View to Camera）ときは履歴を捨てる。正射影ではずらせないので掛からない。フレームを完全一致で比べるスモーク（physics・navigation・showcases）は、Editor::forceAntiAliasing で SMAA に固定する（カメラを通して見ても上書きされない）。ジャギーが作っていた見かけの鋭さは消えるので、SMAA だけの時より少し柔らかく見える。

［補足］モーションブラー（View → Motion Blur (Play)、既定オン、Play 中のみ）。TAA のパスが 2 つ目の出力 Velocity（RG16F）に、各画素自身の動き（ジッタを除き、空はカメラの再投影）を書く。続くクアッドパス（media/postprocess/MotionBlur）が、その動き × シャッター 0.5（180°、最大 32 ピクセル）に沿って 12 標本を取る。McGuire ら（2012）の再構成フィルタ: 16×16 画素のタイルごとの最大の動き（TileMax）と、その周り 3×3 タイルの最大（NeighborMax、media/postprocess/MotionTiles）を求め、標本はこの「周りで最も速い動き」に沿って取る（タイルの参照位置はノイズでずらし、境目を隠す）。こうしないと、止まった背景の画素は自分の動きがゼロなのでぼけず、動く物は自分の輪郭の内側でしかぼけない。標本が手前にあり自分の動きで届くなら、または奥にあり中心の動きが覆うなら数える。そのため動く物は背景にかぶさり、止まった手前の物は動く背景の上でぼけない。深度は投影の z 行 (A, B) で距離 B / (d + A) に直して比べる。標本の位置は画素ごとのノイズでずらし、段差を粒に変える。履歴（TaaHistory）にはブラー前の像を残す。エディターでの視点操作ではぼかさない。

［補足］SSAO（View → Ambient Occlusion、既定オン）。プリパスの直後に、法線と深度から遮蔽を計算する（media/postprocess/Ssao）。法線を軸とする半径 0.5 m の半球に、中心寄りのフィボナッチ螺旋の 12 標本を置き、画素ごとのノイズで回す。深度バッファの面がその点より手前にあれば遮られたとし、半径より遠く離れた面は数えない。次に、深度の近さで重み付けした 5×5 で粒をならす（SsaoBlur）。本パス（use_prepass、キュー 10）では HlmsListener の AmbientOcclusion がこの R8 テクスチャを追加のパステクスチャとしてバインドし、フォークのテンプレートに足したフック custom_ps_posAmbient（間接光の合成直後）で、間接光の拡散と鏡面（envColourD・envColourS）に掛ける。直接光には掛けない。リスナーごとの追加テクスチャの開始スロットは HlmsListenerChain がプロパティ custom_first_texture で渡し、custom_ps_uniformDeclaration ピースは各リスナーの宣言（ssaoTextures、aifTextures）を挿入する。キュー 11 以降（空・パーティクル・吸収体）と半透明には掛からない。

［補足］SSR（View → Screen-Space Reflections、既定オン）。プリパスの後、本パスの前に、法線・粗さ・深度・モーションベクトルと前フレームの画像（TaaHistory、ブルーム前の HDR）から反射を求める（media/postprocess/Ssr）。視線を法線で反射したレイをビュー空間で 32 歩（遠いほど粗く、画素ごとのノイズでずらす）進め、深度バッファの面の後ろ（厚さ 0.3 m ＋ 距離の 5%）に入ったら当たりとし、4 回の二分探索で詰める。当たった点はモーションベクトル（ジッタの変化を除く）で前フレームの位置へ戻して色を取る。アルファは信頼度で、粗さ 0.25〜0.55 で消え、カメラ側へ向かうレイ、画面端、20 m の端で薄れる。結果は OGRE の use_prepass の SSR 入力（setUseDepthPrePass の第 3 引数）として本パスに渡し、HlmsPbs が反射プローブの鏡面の上にアルファで混ぜる。前フレームが別の画（ターゲットの作り直し、ビューが隠れていた、視点の切り替え）のときは使わない。テクスチャを 5 枚読むので、OGRE の標準ルートレイアウト（4 枚）でなく high を頂点・ピクセル両方に指定する。完全一致を比べるスモークは TAA と同様に SSR も切る。粗い面のぼけた反射は未対応（フェードで逃がす）。

［補足］DoF（被写界深度）。Camera コンポーネントに focusDistance（m）と fStop（0 で無効、既定）を足した。ビュー（レベルの Inspector、保存しない）にも同じ値があり、`--capture` はカメラの値を使う。35 mm フルサイズ（センサー高 24 mm）の薄レンズとし、画角から焦点距離 f = 12 / tan(画角/2) mm、口径 A = f / F 値として、錯乱円の直径（画素）= A f / (zf − f) × (z − zf) / z ÷ 24 mm × 画面の高さ。Hdr の後、TAA の前のクアッドパス（media/postprocess/DepthOfField）が、最大半径 16 画素の円盤に黄金角の螺旋で 32 標本を取り、その標本の錯乱円が画素に届くなら、その面積の逆数の重みで集める（scatter as gather）。画素より奥の標本は画素自身の錯乱円までしか広げないので、背景はピントの合った手前ににじまず、ぼけた手前は背景にかぶさる。TAA の前に置き、粒を時間方向にならす。SSAO・SSR・DoF の画素ごとのノイズは、TAA が有効なときだけ毎フレーム黄金比ずつ回し（無効ならちらつかないよう固定）、TAA に平均させる。半透明（キュー 200）は深度を書かないので、背後の面のピントでぼける。

［補足］アルファハッシュ。PbsMaterial コンポーネントに alpha（Opaque／Test／Hash）、alphaThreshold（Test のしきい値、0.5）、opacity（Hash の不透明度、拡散マップのアルファに掛かる）を足した。Hash は HlmsPbsDatablock::setAlphaHashing と、ブレンドしない透明度（setTransparency(opacity, None)、HlmsPbs は F0.w として拡散アルファに掛ける）で作る。Model コンポーネントの alphaHashing は、ファイルの切り抜きマテリアル（アルファ付き DXT5 の拡散マップ）をアルファテスト 0.5 の代わりにハッシュにする（キャッシュキーにも入れる）。OGRE のハッシュ（Wyman & McGuire）はオブジェクト空間で安定するよう作られており、毎フレーム同じ画素が残るので TAA が平均できない。そこでフォークのテンプレートのしきい値計算にフック custom_alphaHashThreshold を足し、HlmsListener の FrameNoise が影キャスター以外の全パスへ渡すフレームのオフセット（TAA が有効なときだけ黄金比ずつ進む、SSAO などと同じ値）でしきい値を回す（fract で一様分布のまま）。同じフレームのプリパスと本パスは同じ値を使うので深度は一致する。影キャスターのパスにはパスバッファが無いので、影は安定したハッシュのまま。TAA の今フレームの重み 0.1 の残差で、広い半透明面には粒が残る。

［補足］透過（Translucency）。PbsMaterial と Model の materials の各変更に translucency = { colour, distortion（0.2）, power（4）, scale（1） } を足した。colour が黒なら無効（保存もしない）。Barré-Brisebois & Bouchard（Frostbite、GDC 2011）の近似で、光源ごとに lightDiffuse × colour × scale × saturate(dot(V, −(L + N × distortion)))^power を足す。フォークは変えない。DeclareBRDF は custom_ps_uniformStructDeclaration（DefaultHeaderPS の先頭近く）の後、custom_ps_functions の前に入るので、データブロックのカスタムピースで前者に #define BRDF throneSurfaceBRDF を置いて OGRE の BRDF を改名し、後者で #undef して、同じ条件（法線あり・プリパス以外・needs_view_dir）の下で改名後の BRDF に透過を足す BRDF を定義する。平行光源・点・スポットのループと Forward+ がすべてこの BRDF を呼ぶ。値は定数としてピースに埋め込み、ピース名は内容のハッシュ（吸収と同じ）。影と減衰は呼び出し側が BRDF の結果全体に掛けるため、厚い物は自身の影で透過も消える（薄い面は影のバイアス内なので透ける）。影マップの深度差から厚みを求める方式は今後の課題。面積光源（LTC・Approx）は BRDF を通らないので透過しない。Model では透過は不透明マテリアルだけに付け、キャッシュキーに含める。

［補足］非表示（hidden）。Model の materials の変更に hidden を足した。真なら、そのマテリアルの面をモデルから除く（描画・境界・表面点のすべて）。Blender の mmd_tools は剛体をメッシュ（マテリアル mmd_tools_rigid_*）として出力し、FBX の表示フラグも立っているので、ファイル側では区別できない。キャッシュキーに含める。

［補足］スキンメッシュのモーションベクトル。ThronePbs は、スキンの描画では描画ごとの行の先頭に「前フレームの骨行列の開始行」を書き、prevWorldBuf の描画ごとの領域の後ろに置いた骨の領域（バッファごとに 256 骨 × 32 描画分）へ、HlmsPbs が書くのと同じ並び（ブレンドインデックス順の 4x3、ワールド空間）で前フレームの骨行列を書く。前フレームの骨行列は Renderable ごとに保持する。VS のピース（hlms_skeleton）は同じ重みで前の位置を出す。領域が足りない描画は -1 を書き、今の姿勢を使う（動きなし）。

［補足］スクリーンスペース SSS（View → Subsurface Scattering、既定オン）。PbsMaterial と Model の materials の各変更に subsurfaceWidth（m、0 で無効）を足した。透過と同じカスタムピース（surfacePiece）が custom_ps_uniformStructDeclaration に #define THRONE_SUBSURFACE_WIDTH を置き、プリパスはモーションベクトルのピースで G-buffer の 4 枚目 GBufferSubsurface（R16F、クリア値 0）にその値（無ければ 0）を書く。Opaque のキュー 10 の直後、キュー 11 以降を描く前に、Jimenez の分離型フィルター（media/postprocess/Subsurface）を 2 回かける。横は Opaque → SubsurfaceHorizontal（幅の無い画素は複写）、縦は SubsurfaceHorizontal → Opaque（深度を付けない RTV OpaqueColour、幅の無い画素は discard）。カーネルは d'Eon & Luebke の肌のプロファイル（6 つのガウスの和、赤が最も遠い）で、その 3σ（8 mm）を面の幅に伸ばす。半径の画素数は 幅 × 投影 ÷ 距離（上限 128）。11 標本はそれぞれ区間を代表し、重みはプロファイルの区間の積分（erf の近似）とする。区間は画素とフレームのノイズで最大半区間ずらし、TAA が平均する。幅の無い面の標本や、深度差が幅に近い標本は中心の色に寄せ、輪郭を越えてにじませない。拡散と鏡面を分けるにはライトループ（影と減衰が BRDF の外で掛かる）にフォークの変更が要るため、今は SSS 面のライティング全体（鏡面のハイライトも）をぼかす。2 パスは実行マスク 0x08 で、オフでは走らない。

［補足］トーンマップは sRGB 符号化した値を書き、以降の SMAA の中間・ビューポートテクスチャは RGBA8_UNORM（sRGB でない）。ウィンドウ（Vulkan スワップチェーン）は gamma 指定なしで UNORM なので、ImGui はビューポートの値をそのまま写す。以前はビューポートテクスチャが RGBA8_UNORM_SRGB で、ImGui のサンプリングで線形へ戻され、その値が UNORM のウィンドウに書かれていた（画面が本来より暗くガンマも違う）。--capture も Image2::getColourAt（sRGB を線形へ戻す）で同じ暗い値を書いていたため、画面とキャプチャは一致したまま誤っていた。キャプチャはバイトをそのまま書く。この修正で Bistro の露出を全て見直した（内装 −1.5 → −2.9 EV など）。

［補足］samples/bistro は ORCA の Amazon Lumberyard Bistro（CC BY 4.0）を 7 レベルで再現する。データ（Bistro_v5_2/）は Git 管理外。

- IrradianceFieldRaster: プローブ i をセル中心（i + 0.5）に置いていたが、PBS シェーダー（と VCT 生成）は格子位置 i として読む。格子位置 i に置く。
- IrradianceFieldRaster: 可視性用の深度を、コメントの意図どおりシェーダーの格子単位（numProbes ÷ fieldSize を掛ける）にする。numProbes だけを掛けていたため深度が領域の大きさ倍になり、遮られたプローブ（建物内など）を一度も棄却しなかった。キューブ面の軸方向の深度を視線方向の距離へ直す（斜め方向で短く出ていた）。
- SceneManager::clearScene: ルートに付いたままのスカイ矩形を再アタッチして例外になっていた。未アタッチ時だけ付け直す。
- PBS テンプレート: 照度場の直後に差し込み口 custom_ps_diffuseGi を足し、照度場用の分岐（球面調和の環境光のフェード、反射の正規化）をプロパティ custom_diffuse_gi でも使う（Adaptive Irradiance Field、12 §5）。

［補足］Point／Spot の Light Component は castShadows を持つ。影ノードは平行光源の 3 カスケードに加え、1024² の FOCUSED 影マップ 4 枠を同じアトラス（4096×4096）に持ち、OGRE がカメラに近い影付き局所光へ割り当てる。点光源はキューブから DPSM へ変換する（Common/DPSM.material を読む）。Bistro 内装では天井灯 4 灯が影を落とす。

### 8.1 モデルの構造表示

Model ステップ（ドリルダウンの最後の段。Context::Kind::Model）でモデルファイルを単体で開く。Browser の Models タブ（プロジェクト内の .fbx／.mesh を、初回表示時と Refresh で再帰的に探す）のダブルクリック、Model を持つノードのダブルクリック、または Model の Inspector の Open Model で入る。ノードから入るとそのコンポーネントの設定（法線規約、emission、マテリアル変更）のまま読む。ステップの内容は Model ノードを 1 つだけ持つ保存しないプレハブ（modelPreview_）で、ビューポートの描画はプレハブのステップと同じ経路を通る。ライティングはレベルの最初のシーンのものではなく既定値（既定の太陽と空）を使う。シーンは太陽を自身の Light ノードに任せる（defaultSun = false）ことがあり、それを流用すると太陽が消え、霞んだ空でグリッドも見えなくなるため。そのノードは選択・編集できない。

Hierarchy は読み込み後の構造を読み取り専用で表示する。parse() がメッシュ配置とは別に Outline を作る: ufbx のルート以下のノードを深さ優先で並べ（親が先、各ノードの直後にその部分木。end は部分木の終わり）、名前、モデル空間での位置・回転・スケール（node_to_world）、骨かどうか、置くメッシュの頂点数・三角形数・使うマテリアル、部分木を含むモデル空間の境界を持つ。メッシュの配置は従来どおりモデル空間へ焼き込んだまま（Outline は表示専用）。.mesh はメッシュ 1 つの行と、スケルトンの骨（バインドポーズ）を並べ、マテリアルは「(plain grey)」1 つ。ノードの行は使うマテリアル名を灰色で添え、骨は [Joint]。末尾の Materials グループにマテリアルを一意に並べる。

選択（Selection::Kind::ModelNode／ModelMaterial、item は Outline またはマテリアルの番号）の Inspector はファイルの値を示す。ノード: 親、モデル空間の変換、境界の大きさ、メッシュの頂点・三角形数とマテリアル（クリックで選択）。マテリアル: 面の種類（Opaque／Alpha Test／Alpha Hash／Refractive／Absorbing volume）、色・不透明度・発光、テクスチャのパス、使うノード。ノードの選択枠はその部分木の境界で、F で寄る。骨は境界を持たないので枠が出ない。選択ノードにはモデル空間の変換の位置に操作不可（ImGuizmo::Enable(false)、灰色）のギズモを出す。ビューポートのクリックは、各ノードが自身で置くメッシュの境界（meshLower／meshUpper、モデル空間）とレイを比べ、最も手前（同じ距離なら体積の小さい方）のノードを選び、Hierarchy で祖先を開いてそこまでスクロールする。三角形単位の判定ではないので、境界が重なる所では手前の箱が勝つ。オーバーライド（ノード単位の変換、表示、マテリアル変更の移設）は今後の課題。

## 9. 間接光（GI）

反射は固定済み OGRE-Next の既存機能、拡散は Adaptive Irradiance Field（12）で、シーンごとに焼き込む（13）。

- 反射: ParallaxCorrectedCubemapAuto（per-pixel）のプローブを領域内の格子に置く。各プローブの影響範囲はセルを 1/4 ずつはみ出し、視差補正の形は領域全体の箱とする（PccPerPixelGridPlacement の深度による形合わせは全プローブを一度に描くため使わない）。256² RGBA16F、GGX 事前フィルタ付き。Forward Clustered のセルあたり 16 プローブ。
- 拡散: Adaptive Irradiance Field（12）。角を共有する八分木の各プローブでキューブを描き、球面調和 L1 へ射影する。以前は IrradianceField のラスタ生成（DDGI 方式、1 つの箱を均一格子で覆う）を使った。下の照度場の補足は、そのときの記録。

［補足］IrradianceField::update() はパラメーター（処理開始プローブ番号）を永続マップのバッファに書き、同じフレームの 2 回目の呼び出しが GPU の積分前に上書きする。1 フレームに update(1) を繰り返すと、最後のプローブだけが積分され、他は生のキューブ（放射輝度）と生の深度のまま残る（照度場が暗くまだらになっていた）。焼き込みは照度場の update を 1 フレーム 1 回とし、その本数を前フレームの所要時間で倍・半分に調整する。OGRE は場を 1 セル分ずつ広げてからプローブを格子位置に置き、シェーダーは最後のプローブの先を読めない（次の行へ回り込む）。そこで initialize に渡す原点と大きさを逆算し、各軸の最初と最後のプローブを GI 領域の面に置く（1 本なら中央）。領域の下面は地面より少し上にする。地下のプローブは裏面カリングで地面越しに空を見る。

シーンの lighting.gi（以前はレベルの rendering.gi）が領域（lower／upper、シーンの座標。反射プローブと Local の Adaptive Irradiance Field の範囲）、反射プローブ数、bounces、Adaptive Irradiance Field の設定（12 §3）を持つ。焼き込みは Inspector の Bake、Lighting メニューの Bake Global Illumination か `ogrethrone --bake-gi <folder> [file] [level]`。反射プローブ、続いて拡散のプローブを 1 フレーム約 0.1 秒ずつ（反射プローブは少なくとも 1 つ）描き、その間ウィンドウは応答し続け、進捗ウィンドウにパス数・描いたプローブ数・プログレスバーを出す（§10）。ファイルの読み込みとマテリアルの表示が終わるまで待ってから始める。最初のパスは既存の焼き込みを外し、HDR 環境の球面調和と反射だけで照らしたシーンを描く。以降のパスは 1 フレームごとに直前の焼き込みを使ったシーンを描くので、パスごとに 1 回分の照り返しが増える（bounces、既定 2）。

焼き込み結果はプロジェクトに保存する。シーン `scenes/x.scene.lton` の結果は `scenes/x.gi/` に、シーンの座標で置き（13。以前はレベルの `levels/x.gi/`）、gi.lton（設定、焼き込みの所要時間（全パス、ファイル読み込み待ちを除く。Inspector の使用中の焼き込み名の横に出す）、各反射プローブの位置・領域・形）、reflections.oitd（全プローブのキューブ配列とミップ）と、Adaptive Irradiance Field の表（diffuse-top / nodes / cells / probes.oitd、12 §3）からなる（形式の版 3。照度場の版 1、レベルの焼き込みの版 2 は読まない）。レベルを開くと読み込み、描き直さない（PCC は一時停止したまま）。GI が有効で焼き込みデータがあれば、焼き込み時の設定（gi.lton に記録）のまま使う。レベルの設定が焼き込み時と違えば、Inspector に再焼き込みを促す警告を出す（使うのをやめない。設定を少し触っただけで長い焼き込みが外れていたため）。GI を無効にすると外し、有効に戻すと読み直す。

GI の使用中も HDR 環境があれば環境光は AmbientSh のまま。Adaptive Irradiance Field の範囲の中はそれだけを拡散光とし（EnvFeatures_DiffuseGiFromReflectionProbe は切る）、外は球面調和へ移る（下記、照度場のときと同じ重み ifdWeight）。HDR 環境がなければ環境光を切る。マテリアルの反射マップに HDR 環境を割り当てない。割り当てると OGRE は手動 PCC として扱い、シェーダーが壊れる（toProbeLocalSpace の不一致）。空は HDR 環境のまま描く。プローブ撮影は描画キュー 0〜199 と 201〜249（屈折ガラスの 200 と PCC 補助の 250 を除く）を、エディターの影ノードで描く（media/gi/ThroneGi.compositor）。

レベルの environmentScale は HDR 環境の放射輝度そのものに掛かる（空・プローブ撮影・反射・環境光）。environmentTemperature（K、0 で無効）はそれに黒体色を掛ける。読み込み時の打ち切りは 16（スケール前）で、HDR 内の太陽は Light に任せる。Light Component は色温度（K、0 で無効、6500 K が白）を持ち、色に黒体色を掛ける。

箱外のフェード: 照度場は最外周のプローブの外も端のプローブにクランプして読むため、GI の箱の外では誤った光と、箱の面（軸に平行な平面）に沿った硬い境界の筋が出ていた（exterior の箱の外にある Le Petit Coin のテラスなど）。fork で、照度場のパスバッファの空き 2 要素に Z 方向のプローブ数と、フェード幅（1 セル）を入れる。シェーダーは格子座標で最外周のプローブからの距離を求め、半セル以内は重み 1、そこから 1 セルかけて 0 にする。半セルの余裕は、最下層のプローブより少し下にある地面を照度場のままにするため。拡散光は「照度場 × 重み + 球面調和 × (1 − 重み)」。反射プローブは箱の外にない（反射が 0 で、金属が真っ黒になる）ので、同じく「球面調和を反射方向で評価した値 × (1 − 重み)」を反射に足す。反射プローブの重みの総和で切り替えると、箱の中でもプローブの届かない面（地面の一部など）が明るくなりすぎるので、箱の重みを使う。

照度プローブのキューブの far は箱の対角の 2 倍に固定。far を設定で短くする案（gi.probeFar）は試して不採用: Bistro（照度場 1,024 本）では 15 m でも速さは約 10% しか変わらず、遠くの物が遮っていた空が見えて明るさが 1 割以上上がった（光漏れ、12 §4）。

デバッグ表示: View → GI Probes で、プローブの範囲（白。Global なら場面の境界、Local なら GI の箱）、各反射プローブの影響範囲（青）、Adaptive Irradiance Field（12）のプローブ位置（十字。周りのセルの最も細かい段で色分け：L0 黄、L1 緑、L2 水色、L3 青、L4 紫、L5 赤。補間で決まるぶら下がり点は灰）を線で描く。Show Surface Points で表面点も描く。エディターの選択枠と同じ ManualObject の線描画を使う。OGRE の IfdProbeVisualizer（照度で色付けした球）は、静的ノードに置かれて描画されないうえ、終了時の資源破棄の順で落ちたので使わない。

反射の正規化: 反射プローブは自分の位置から見たシーンを持つので、日除けの下や室内の面には、そこへ届かない明るい景色が映る。粗い面ほど低いミップ（周囲の平均）を引き、それが直接光と照度場の小さい日陰で支配的になる。Bistro のテラスでは粗い木と床が紫・緑に色付いていた（どのプローブの何色の平均が勝つかで色が変わる）。fork の Forward+ キューブマップピース（照度場があり、cubemaps_as_diffuse_gi でないとき）で、プローブが法線方向に見た拡散光（最低ミップ）と照度場のその点の拡散光の輝度比の 2 倍を反射に掛ける（1 を超えない）。照度場は半球の平均でプローブの最低ミップより空を少なく見るので、比そのままでは日向の金属（街灯の柱）まで黒くなる。2 倍なら日向は弱めず、テラスの色化けも出ない。

samples/bistro の 7 レベルで焼き込む。外観は太陽 power 90・4300 K・南西から仰角 45°（影の落ち方を参照 2 枚に合わせた）、environmentScale 28・environmentTemperature 5000、露出 −2.5 EV（terrace −2.7）。太陽と空の比は輝度分布の幅（日陰と日向の差）を参照に合わせて決めた、照度プローブ 16×4×16（y 0.5〜14）。内装は −2.9 EV。参照画像（中央切り抜き）との比較:

- plaza: 平均 RGB 104/97/95（参照 103/102/100）、輝度の 10／25／50／75／90 パーセンタイル 25/43/80/159/204（参照 20/41/89/153/218）、40×25 格子の輝度相関 0.88。日除け 116/48/55（参照 119/43/56）、日向の石畳 134/130/132（参照 127/127/126）。

焼き込み結果（1 レベル約 50 MB）は素材と同じく Git 管理外とする。Release ビルドでの焼き込みは 1 レベル 25〜60 秒。

［未決］参照はパストレースなので、日陰と室内の明るさ・色は近似にとどまる。参照の方がハイライトがやや明るい（外観の p90 で 14〜35 高い）。構図は目視合わせで、参照のカメラ姿勢とは一致しない。

［補足］均一格子の照度場は 1 つの箱しか覆えない。広い場面を自動で覆う適応的なプローブは 12 で設計する。

## 10. 読み込みと進捗

時間のかかる処理は Tasks（src/editor/Tasks.h）に登録し、エディターはその間もフレームを描き続ける。ウィンドウが「応答なし」になったり真っ暗になったりしない。

- ステップ: 毎フレーム主スレッドで少しずつ進める関数。完了で真を返す。GI の焼き込みとマテリアルの表示がこれ。
- バックグラウンド: ワーカースレッド（std::async）で走らせ、結果を主スレッドの完了関数へ渡す。OGRE を呼ばない処理だけを置く。FBX の解析（ModelLibrary::parse）、HDR 環境のキューブマップ・球面調和変換（readEnvironment）、GI 焼き込み結果の読み込み（GlobalIllumination::read）。GPU への転送は完了関数で行う。
- 表示: 実行中のタスクを中央の Working ウィンドウに並べる。進捗が分かるものはプログレスバー、分からないもの（ファイルの読み込み）はスピナー。ステップはその表示が 2 フレーム描かれてから始める（最初の 1 フレームで表示が画面に出る）。

シェーダーは初めて描かれるときにコンパイルされる（Debug で 1 本約 1 秒）。モデルの Item は非表示で置き、"Preparing materials" ステップが 1 フレームに新しいマテリアル 2 つ分ずつ表示する。読み込み中のファイルがあれば待つ。環境マップや焼き込み結果が後から届くとパスが変わり、表示済みのシェーダーを全部作り直すため。OGRE はアタッチ時に可視へ戻すので、非表示はアタッチの後に設定する。

［補足］Bistro 内装の Debug 実行で、最長フレームは 38 秒から約 2 秒になった（シェーダー 383 本 → 37 本）。

［提案］残りのコンパイル待ちは、SceneManager のワーカースレッドを 2 以上にすれば OGRE の並列コンパイル（ParallelHlmsCompileQueue）で縮められる。現在は 1。
